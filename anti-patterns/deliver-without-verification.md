# 反模式：未验证即交付

## 症状
- 代码生成完就说"搞定了"
- 用户打开后发现页面打不开/空白/乱码/样式错乱
- 用户反复指出同类问题

## 腐烂路径

```
第1次: 交付未验证 → 用户发现问题 → 用户提醒
第2次: 交付未验证 → 用户发现问题 → 用户开始烦躁
第3次: 交付未验证 → 用户发现问题 → 交付信任崩塌
```

最终：用户不再信任后续任何交付物，每次都要亲自验证。

## 根因

- 将"代码正确"等同于"任务完成"
- 缺少用户视角验收流程
- 流水线式机械输出，不思考用户体验

## 预防

1. **强制验收清单**：每次交付前对照 `templates/checklist/user-acceptance-checklist.md` 逐项自检
2. **真实验证**：不只是"想"——真的打开页面、真的点击按钮、真的模拟用户
3. **P0 红线**：页面打不开、空白、乱码 = 绝不可交付
4. **用户优先**：用户说有问题 → 先排查环境，不先假设用户操作失误

## 示例：图标更新失败

```
用户: 图标没变化
我的错误反应: 是不是你没刷新？
正确反应: 立刻检查 — 快捷方式路径？ICO 文件存在？编码问题导致 COM 失败？
根本原因: COM 对象处理中文路径失败，图标从未真正更新
```
