# 抖音自动续火花部署包

## 基本信息

- **日期**：2026-08-22
- **需求**：Windows 扫码登录并抓取本人账号状态，部署到 Linux，提供网页配置
- **交付形态**：Windows 状态获取入口、Linux 一键部署脚本、网页配置与运行说明
- **最终状态**：部署包和文档存在；没有证据证明登录、服务器部署、dry-run 或正式运行实际成功

## 设计链路

```text
Windows 本人扫码登录
  -> 生成敏感登录态 state.json
  -> 安全传输到本人 Linux 服务器
  -> 网页使用访问 token 登录
  -> 同步联系人并选择小范围对象
  -> 模拟运行
  -> 人工检查日志
  -> 低频正式运行/每日计划
```

Windows 入口负责准备 Python 环境、安装浏览器自动化依赖、打开抖音登录页，并在用户本人扫码后生成 `data/state.json`。Linux 部署面向 Ubuntu 22.04/24.04 或 Debian 系统，文档建议至少 1 CPU、1 GB RAM 和常规公网网络环境。

## 凭据边界

`state.json` 本质上等同登录凭据，而不是普通配置文件：

- 不发给他人。
- 不上传公开 GitHub、网盘公开链接或聊天截图。
- 不写入日志、README、Issue 或错误报告。
- 服务器端限制文件权限和 Web 访问 token。
- 一旦怀疑泄露，立即退出相关会话并重新登录生成。

知识库只记录流程和风险，不记录任何真实状态内容。

## 正确的启用顺序

1. 网页登录后上传状态文件。
2. 只同步并选择少量明确对象。
3. 保存配置。
4. 先运行“模拟运行”，检查会联系谁、会执行什么。
5. 模拟结果正确后再人工触发一次正式运行。
6. 稳定后才设置低频计划，最多按实际需要每日一次。

不能把“网页可以配置”和“脚本能启动”当作“账号自动化已稳定可用”。

## 风控与合规边界

该方案是浏览器自动化，不是官方 API。它存在安全验证、频率限制和账号处罚风险。长期规则：

- 只用于本人账号和本人明确选择的关系。
- 不做批量营销、陌生人触达或高频重试。
- 出现“操作频繁”、验证码或安全验证时立即停止。
- 不尝试绕过平台验证或隐藏自动化行为。
- 平台规则或页面结构变化后必须重新验证。

## 验证结论

现有证据只能支持：包、脚本入口和操作说明已经形成。它不支持以下表述：

- “Windows 登录态已成功抓取”。
- “Linux 服务器已部署成功”。
- “网页配置已验证”。
- “续火花任务已实际执行”。
- “定时任务稳定运行”。

未来执行时应保存脱敏运行日志：时间、阶段、对象数量、dry-run/real、结果分类和停止原因，不保存消息内容或凭据。

## 可复用结论

- 安装包、操作手册和执行日志是三种不同证据。
- 浏览器状态文件按密钥管理，不按普通附件管理。
- 高风险自动化先 dry-run，再小范围、低频正式运行。
- 平台风控信号是停止条件，不是重试挑战。
