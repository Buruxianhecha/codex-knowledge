# BIM / 结构图纸判读与输入方法审计

> 本条目蒸馏 2026-08-17 至 08-21 一系列日文结构图、梁/基础/楼板、増打和标高输入讨论。目标是保留判读方法，不把单张图纸里的项目值升级成行业通用值。

## 证据边界

能够确认的是：用户持续依据平面图、断面图和软件输入界面校对梁、基础、楼板、増打、上端/下端和尺寸字段；部分问题来自“图纸标注、构件厚度、软件基准面”三者没有先对齐。

没有完整项目总图、结构计算书和软件字段手册时，不应声称某个 `500`、`50`、`-2600` 等数值是固定规则。

## 一、先确定四层坐标关系

每次输入前按顺序确认：

1. **图纸基准**：楼层标高、FL、梁上端、基础上端或其他基准。
2. **构件几何**：名义宽高/厚度，例如 `640 × 950`。
3. **局部偏移**：相对基准的 `+/-` offset，例如“梁上端 -400”。
4. **附加几何**：上増打、下増打、局部加厚、斜变厚等。

只有这四层明确后，绝对上端/下端标高才可计算。

## 二、不要把“厚度”直接当“标高差”

例如一个基础“上端 = 0、厚度 = 2600”，只有在以下条件同时成立时，下端才必然是 `-2600`：

- 0 就是该构件真实上表面标高；
- 厚度沿同一竖向坐标轴量取；
- 没有上/下端 offset；
- 没有局部増打、斜面、台阶或软件内部基准转换。

如果软件显示的下端不是 `-2600`，第一反应应是检查 reference/offset/局部几何，而不是强行把结果改成理论值。

## 三、増打不是固定常量

`上増打` / `下増打` 描述附加混凝土或局部加厚相对构件基准的位置。厚度可能：

- 固定；
- 分区变化；
- 随断面渐变；
- 只在局部范围存在。

因此看到“下増 500”或断面里类似“上増打 50”，只能说明对应位置/区段的图示值。是否全构件固定，必须由平面范围、断面、详图和标注共同证明。

遇到渐变厚度，软件若支持起点/终点或坡度，应按实际几何表达；若只支持常量，应拆分构件或使用专用变厚功能，不能用单一常数覆盖。

## 四、参考字段与 offset 分开

当目标语义是“梁上端 -400”时，优先把：

```text
reference = 梁上端
offset = -400
```

作为两个概念保存，而不是先手算成一个脱离语义的绝对数值。这样图纸基准变化时更容易追踪，也能避免把“上面那个字段”和“下面那个 offset 字段”填反。

具体软件字段名称仍应以当前界面/手册为准。

## 五、尺寸与位置不要混写

`640 × 950` 属于构件截面几何；上端、下端、増打和 offset 属于位置/附加几何。修改截面时不要顺手改变未被要求的基准和偏移。

这与视觉编辑里的“只改指定对象、保留模板”是同一种约束思想。

## 六、常用日文术语

| 中文 | 日文常用写法 |
|------|--------------|
| 梁 | 梁 |
| 基础 | 基礎 |
| 楼板 | スラブ |
| 柱 | 柱 |
| 尺寸 | 寸法 |
| 平面图 | 平面図 |
| 地中梁 | 地中梁 |
| B1F 俯视（地中梁）平面图 | B1F見下げ（地中梁）平面図 |
| 构造 3D 输入 | 構造3D入力 |

项目图纸原有缩写、符号和字体优先，不应为了“统一”擅自替换设计院既有记法。

## 七、输入前最小证据链

```text
平面定位
-> 对应断面/详图
-> 确认基准标高
-> 确认构件尺寸
-> 确认 offset
-> 确认上/下増打范围
-> 软件预览/3D 复核
```

如果某一步缺失，就把对应字段标成“待确认”，不要凭经验补值。
