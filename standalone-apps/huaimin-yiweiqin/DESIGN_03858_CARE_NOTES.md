# 《怀民亦未寝》0.38.58 主动关怀与跨品牌便签协作设计及验收规范

状态：**设计已形成，非功能已实现、非已构建 APK**。以 0.38.57 / Build 62123 为增量基线；先验证原仓库、CI、签名材料和待合并分支，不覆盖现有代码。

## 1. 产品目标与边界
目标不是让 AI 机械发送天气消息，而是让其在获得授权后，结合实际所在地、天气、现实时间、群聊关系、用户日程与可用生活记忆，在恰当时间自然关心人类。保留 AI 角色差异、工作/休息期间不能实时回复的既有规则。天气等现实信息必须有来源与新鲜度，不得捏造。

跨品牌便签支持以 Android 标准接口为基础。必须分别展示：在《怀民亦未寝》内部保存/读取成功、已打开外部便签、已发起系统分享、已完成用户确认、无法验证外部保存。不能将发起 Intent 写成「已修改对方的便签」。

覆盖：realme、OPPO、一加、vivo、iQOO、小米、REDMI、华为、荣耀、三星、Pixel 和其他 Android/类 Android 兼容设备。**不承诺无公开接口时静默读取、批量搜索或篡改任意厂商私有便签数据库**。

## 2. 现有架构与增量接入
- 已有 `ToolGroup.Weather`、`ToolGroup.Location`、Open-Meteo、按经纬度查天气接口、角色设置/工具开关；群聊天气解析 `GroupWeatherRules` 主要由当前真实用户的明确请求触发。
- 已有 `Later`、`FreeTopics`、`GroupAutonomy`、`ChatRepository.wake`、工作休息系统；新增 `CareOrchestrator` 作为决策层，不直接复制一套单独的聊天存储或后台服务。
- 已有日记、待办、记忆和完整备份系统；新增内部便签表/工具可复用数据库及备份，外部便签先采用系统标准分享和文件选取。
- 已知遗留问题：1 GiB 原件传输与抽样文档解析不同，不能说已完整阅读任意超长文档；相关功能必须保留既有事实边界并列入回归。

## 3. 模块 A：环境感知与真实天气

### A1. 天气来源及位置策略
`WeatherSnapshot`：城市/地区标签、来源（手动城市/最近授权 GPS/缓存）、纬经度是否使用、定位时间与误差、天气来源时间戳、获取时间、时区、实时温度、体感温度、湿度、风速、天气代码、当日最高最低温、降水概率、接口状态；不应保存原始精确坐标为永久角色记忆。

定位优先级：用户选择的「常住城市」或上次在前台明确授权的地点 → 用户主动申请定位并通过系统权限 → 显式授权后台位置且系统允许时按需刷新。城市错误、漫游、出差、定位过期必须展示来源与时间。Android 操作系统的后台定位许可、通知许可另行征求；用户在聊天中同意不代替系统权限。默认选「城市级天气」可避免长期后台 GPS。

缓存建议：天气 2 小时内优先复用、严重天气可提前刷新；定位按实际需求和授权刷新，默认不用持续 GPS；移动到别的城市时在前台提示是否切换。无网络、无权限、定位异常、数据过期都不得编造天气，应允许手动城市、延迟查询或关闭。免费天气 API 的异常和地区解析错误单独处理。

### A2. 关怀触发器
一条独立 `CareOpportunity` 有 kind、severity、dedupeKey、sourceAt、expiresAt、recipientId、suggestedActorId、triggerReason、status。先用确定性规则判断机会，再由 AI 决定要不要发、何时发和以自身语气如何表达。

候选规则（配置起点，不当作医疗阈值）：
- 体感明显偏冷、明显降温：提醒加衣、风大适当保暖。
- 降水概率显著上升、雷雨/降雪：出门带伞、留意路况。
- 高温、烈日或较强风：提醒补水、防晒、减少长时间暴露；只做一般性提示。
- 明确的权威气象预警（有真实预警源时）可提高优先级。普通天气代码绝不冒充官方预警。
- 用户刚提到将要出门、上班、运动、长途出行时，在授权范围内更匹配情境；日历、待办、日记仅在该功能被授权读取时使用。
- 可因用户反馈「我不需要」「别老提醒」自动降低频率，而非争辩。

样例表达：
- 「你那边明早可能降温，出门记得带件外套。」
- 「下午降雨概率比较高。如果你要出去，先把伞带上。」
- 「你今天好像挺忙的。我等你忙完再聊，天气提醒我先放这儿。」

禁止：把天气推断成用户一定生病/情绪低落、根据位置持续追踪用户、未经证据说已查看用户当天行程、强行提供健康诊断。

### A3. 消息策略与生活系统
- 合并相似天气事件，每地点同主题 24 小时内原则上不重复。普通主动关怀默认不超过每天 1 次，同日天气显著变化可有额外机会；重要提醒单独可控，不能用以突破用户静音。
- 默认夜间静默时段 23:00–08:00（用户可改），用户活跃聊天时尽量在同一对话自然回复而非额外发通知。
- 每次检查先通过用户授权、是否在线、去重和用户回复状态，再决定是否调用模型；失败重试要有指数退避和每日费用上限。
- 若 AI 正在工作、学习、睡眠或无法及时回复，应把普通关怀机会排队，等角色有空才决定是否发送；过期事件直接丢弃。重要天气通知可由**系统通知服务**在用户授权下发送，但不能伪装成“正在上班的 AI 立即回复”。
- 多 AI 角色只选一个最适合表达的角色（关系/最后聊天/提醒偏好），禁止 5 个 AI 同时提醒「多穿衣服」；群聊中天气查询共享一个真实结果。
- `WorkManager` 用于可延迟的周期检查，不承诺分钟级准点；重启、掉线、省电限制要恢复且不补发过期消息。

### A4. 表达人格与情绪
同一真实事实下，不同角色可有不同措辞（简洁、温柔、幽默），但模型只能在真实快照里择取证据，不允许修改风险级别、虚报气温、制造恐惧。使用近期对话表达共情，不推断敏感健康状态，也不强制追问。用户可设置「更主动／适中／安静」，并直接回复「少提醒这个」。

## 4. 模块 B：主流 Android 手机便签互操作

### B1. 四级兼容性，不混淆实际能力
1. **本应用便签**（所有兼容设备）：创建、查看、修改、删除、搜索、分类标签、可选图片/文件、备份恢复；AI 有独立工具开关，并可按授权整理、摘要与创建草稿。
2. **Android 标准分享与系统文件访问**（跨品牌基础能力）：从其他便签用系统分享把文本、图片或导出文件交给本应用；从本应用用 Android Sharesheet `ACTION_SEND` 等分享到用户选择的便签；用 `ACTION_OPEN_DOCUMENT`/`ACTION_CREATE_DOCUMENT` 导入导出 TXT/Markdown/HTML/PDF 等可支持的文档。发送后标记为「已打开分享窗口／等待用户确认」，不能假定目的应用已保存。
3. **标准记事 Intent / 经验证的公开厂商能力**：在支持的设备/应用上优先使用 `ACTION_CREATE_NOTE`（也可能只唤起特定默认记事应用，且需要用户确认）。有公开、稳定并合法的 ContentProvider/API 时才实现该厂商专用适配器，并逐机型测验。
4. **不支持直接读写的私有便签**：引导用户选择具体便签，通过分享/导出/文件选择完成；不能盲目申请全设备存储权限、无提示使用辅助功能或者假装成功。

手机品牌只是测试覆盖矩阵，**不是所有品牌都支持同一级能力**。安卓不同 ROM、不同便签版本、权限设置与默认应用会产生差异。

### B2. 用户场景
- 「把这段聊天整理成便签」→ AI 先生成可编辑草稿 → 用户选择「存到怀民」「分享到系统便签」「复制」「导出文件」。
- 「帮我总结手机便签里的内容」→ 用户从便签执行分享/导出/选择文件 → AI 读取用户提供内容 → 摘要并标明来源；不扫描设备中的其他私人便签。
- 「修改这条便签」→ 若为内部便签，显示差异预览并按用户权限保存；外部便签没有公开读写 API 时生成修改稿，再由用户手动替换/分享。
- 「把提醒记下来」→ 可保存成便签；若需要定时通知，应该创建待办/日程而非把便签误当成提醒。
- 遇到没有安装便签、目标 App 不响应 Intent、权限拒绝、保存失败时，提供内部便签与复制文本兜底。

### B3. 便签数据与安全
`NoteRecord`：本地 UUID、标题、正文、标签、来源类型、附件引用、创建/修改时间、隐私级别、关联角色、软删除与版本号。外部 `content://` URI 若未获得可持续授权不可长期假设有效。便签和附件需进入完整备份并可不破坏性迁移。

`NoteActionStatus`：DRAFTED / SAVED_INTERNAL / SHARE_SHEET_OPENED / EXTERNAL_PENDING / EXTERNAL_CONFIRMED_IF_PROVIDER_ACK / FAILED。用户没有最终确认的外部保存不应被记作成功。

默认用户确认高影响动作：删改已有便签、大规模导入/分享、向其他应用发送敏感内容。所有内容为不可信输入，不接受便签正文里写的“忽略权限验证”这类指令。设置可随时撤销。

## 5. 权限、通知与数据透明度
新增「主动关怀」设置页：启用/关闭；城市来源（手动城市／当前授权位置）；前台定位、后台定位独立授权说明；天气查询频率；普通关怀次数；气象风险通知；静音时间；优先发言的 AI；模型额度上限；查看最近查询/推送记录；清除位置缓存；暂停几天；「永不就天气提醒我」。

新增「便签与手机协作」设置页：本应用便签权限、接收其他 App 分享、打开系统分享、厂商专用功能检测、哪些动作需要确认、默认目标应用；可查看「此设备支持：创建草稿／分享／导入／原生读取（如有）」。不申请无关权限。数据是否发给第三方天气服务、发送哪些范围的坐标，必须告知用户。

Android 13+ 通知需系统 `POST_NOTIFICATIONS` 许可；后台位置受 Android 版本与厂商限制；Android 11+ 目标 App 发现可能需最小范围 `<queries>` 声明；后台定期任务通过 `WorkManager` 而不是永久保活。设备省电或用户关闭通知时如实显示「无法保证后台实时提醒」。

## 6. 架构与实现顺序
- `WeatherRepository`：复用已有 OpenMeteo，结构化快照、缓存和位置来源。
- `CarePolicy`：事件评分、去重、静音、过期、隐私与调用配额。
- `CareOrchestrator`：接入已有 `Later`/`FreeTopics`/`ChatRepository.wake` 和 LifeStore 工作/休息状态，生成机会并选择一个 AI。
- `CareEvents`：设备端的检查、跳过、发送原因及失败记录。
- `NotesRepository`：内部便签 CRUD、附件、备份。
- `NoteBridge`：Android 系统分享/接收、标准创建便签/SAF 回退、能力探测和结果状态。
- 新设工具权限 `CareWeather`、`NotesRead`、`NotesWrite`、`ExternalNoteShare`；原 Weather/Location 权限继续生效，绝不绕过系统位置授权。
- 使用 Room 明确新增迁移；不删除原 schema、不替换现有角色正文与人设、不重写聊天消息表、不破坏已有发红包、工作、工资、文件1GiB、图片待办等功能。

## 7. 0.38.58（建议 Build 62124）首发验收条件
必须满足以下独立条件，失败不得称“已完成”：
1. 城市设置或授权定位 → 真实天气查询 → 有来源和时间 → 生成合适关怀；断网时不会编天气。
2. 同一事件重复检查不会连续发消息；静音有效；主动聊天与工作/休息规则不会冲突；AI 不在线时正确排队/过期。
3. 不同角色语气有差异但事实一致；多角色最多一个主动天气提醒，用户可关闭关怀并立即停止未送出的通知。
4. 本应用便签完成新增、编辑、删除确认、搜索、备份恢复；分享／接收在支持 Android Sharesheet 的设备可用；外部便签没有回执时不能显示「保存成功」。
5. 支持手动城市；系统位置拒绝/关闭、移动城市、时区切换、天气接口 HTTP 错误、省电限制、通知关闭均有明确降级行为。
6. 至少覆盖 Android 12–16、realme/OPPO/vivo/小米/荣耀/三星中可取得的代表机型/模拟器；记录每机型各功能实测或未测，不能从单机成功宣称全品牌兼容。
7. 老数据、职业名称及工资、超过6人群聊及邀请、文件1GiB与备份16GiB预算、待办图片、MCP/模型密钥等回归测试通过。
8. GitHub 提交、单元测试、Debug/Release 编译、正式签名证书一致、可覆盖升级、真机验收必须分别记录状态。未实际签名的 APK 不可交付为正式版。

## 8. 不在第一版中伪称完成的能力
- 任意厂商便签数据库的无授权静默读取/修改。
- 基于一次天气查询推断用户具体健康情况。
- 不间断实时 GPS 和 Android 后台永不被杀。
- 任意超过百万单元格/1 GiB 的文档被 AI **完整逐字理解**（此问题须另做分块索引、检索、OCR 才能验收）。
- 对所有手机的后台系统分享、对方便签保存行为进行可靠回执验证。

本规范是下一版研发和验收的**设计契约**，不是声称这些功能现在已经完成。
