# 用户验收清单

> 每次任务交付前逐项自检。P0 项未通过 = 不得交付。

---

## 禁止在验证前使用的表述

- ❌ "应该已经修复"
- ❌ "理论上正常"
- ❌ "现在可以了"
- ❌ "大概率没问题"

只有逐项验证通过后，才能说"已完成"。

---

## P0 必检（未通过 = 任务未完成）

- [ ] **页面/文件能打开** — 双击能否正常打开？能否正常访问 URL？
- [ ] **不空白** — 打开后有实际内容，不是白屏/空文件？
- [ ] **中文不乱码** — 所有中文字符正常显示，无 `????`、无 `锟斤拷`？
- [ ] **功能可交互** — 按钮能点击？链接能跳转？表单能提交？
- [ ] **响应与需求一致** — 实际行为与用户要求是否匹配？

## P1 应检

- [ ] **样式不错乱** — 布局是否正常？元素是否重叠/错位？
- [ ] **控制台无报错** — F12 打开开发者工具，Console 无红色错误？
- [ ] **修改真正生效** — 改完的结果和改前不一样？（不是"改完还是老样子"）
- [ ] **操作路径通畅** — 模拟用户从头到尾走一遍，无中断？

## P2 可检（完整用户路径 + 边缘情况）

- [ ] **用户如何进入** — 入口是否明确？用户知道从哪里开始吗？
- [ ] **用户第一眼** — 打开后第一眼看到的内容是否符合预期？
- [ ] **用户点击顺序** — 模拟自然操作流程是否顺畅？
- [ ] **是否容易误解** — 有没有歧义的文案或布局？
- [ ] **能否完成目标** — 从进入到完成，用户能成功吗？
- [ ] **移动端兼容** — 缩小浏览器窗口，布局是否自适应？
- [ ] **空输入处理** — 什么都不输入提交，会崩溃吗？
- [ ] **超长输入** — 输入极端长的内容，布局/功能正常吗？
- [ ] **其他功能未受影响** — 改 A 功能，B 功能还能用吗？

## 用户反馈时的排查顺序

```
优先：复现问题（实际环境操作，而非仅分析代码）
↓
1. 环境     → 操作系统版本、依赖版本、PATH 是否正确
2. 兼容性   → 浏览器类型/版本、运行时差异
3. 缓存     → 浏览器缓存、编译缓存、CDN 缓存
4. 编码     → 文件编码(UTF-8? GBK?)、换行符(CRLF?)、BOM
5. 路径     → 硬编码路径是否存在？空格/中文路径？
6. 运行时   → 实际报错日志、进程状态、端口占用

如无法复现，主动列出：
- 可能环境差异
- 潜在触发条件
- 用户侧可验证信息
- 下一步排查路径
```

## 重复错误风险升级机制

| 次数 | 动作 |
|------|------|
| 第1次 | 正常修复 + 记录到 mistakes/ |
| 第2次 | 标记 risk:high + 同类型任务强制预检 |
| 第3次+ | 写入 anti-patterns/ + 所有任务前置检查 |

---

## 使用方式

1. 任务完成前，复制此清单
2. 逐项执行检查（不只是"想"，是真的打开文件/页面看）
3. 模拟完整用户路径走一遍
4. P0 全部通过后才交付
5. 如用户反馈问题，回溯此清单，找出漏检项
