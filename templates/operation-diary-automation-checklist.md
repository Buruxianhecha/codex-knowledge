# 操作日记自动化检查清单

用于每日或定时自动生成操作日记，并同步到 GitHub 与长期知识库。

## 1. 读取上下文

- [ ] 读取自动化 memory。
- [ ] 记录上次运行时间。
- [ ] 提取上次有效路径、提交哈希和项目名。
- [ ] 用显式 UTF-8 读取自动化配置，检查是否存在乱码路径。

## 2. 确认日记仓库

- [ ] 列出候选 `codex-diary` 仓库。
- [ ] 对每个候选仓库执行 `git status --short --branch`。
- [ ] 对每个候选仓库执行 `git log --oneline -n 8`。
- [ ] 选择包含上次有效提交且与远端同步的仓库。
- [ ] 写入前执行 `git pull --ff-only`。

## 3. 收集证据

- [ ] 读取近期日记，但只把它当作事实来源，不盲目复制格式。
- [ ] 检查今日相关仓库、工具配置和知识库目录。
- [ ] 如果大范围递归扫描超时，改为扫描高信号目录。
- [ ] 如果终端显示乱码，先用显式 UTF-8 读回确认，再判断是否真正损坏。

## 4. 编写日记

- [ ] 今日完成事项。
- [ ] 遇到的问题与解决过程。
- [ ] 新获得的经验、知识或模式。
- [ ] 重要决策与原因。
- [ ] 待办事项与下一步计划。
- [ ] 值得沉淀到长期知识库的内容。
- [ ] Skill、工作流或工具配置变更影响。

## 5. 更新知识库

- [ ] Lessons：沉淀可复用经验。
- [ ] Patterns：沉淀可复用流程。
- [ ] Mistakes：记录错误案例和预防规则。
- [ ] Decisions：记录关键决策和原因。
- [ ] Templates：沉淀下次可直接复用的清单。
- [ ] 只 stage 本次新增或明确修改的文件。

## 6. 验证与发布

- [ ] 读回新日记，确认中文无乱码。
- [ ] `git diff --check`。
- [ ] `git status --short` 确认只包含预期文件。
- [ ] 提交日记仓库。
- [ ] 推送日记仓库到 GitHub。
- [ ] 如知识库也提交，确保不混入既有脏变更。
- [ ] 更新自动化 memory，记录本次路径、提交和未完成事项。

## 失败处理

- 如果找不到最新仓库：停止写入，先列出候选路径和提交差异。
- 如果新文件读回乱码：不要提交，先修复编码。
- 如果知识库工作区已有脏变更：只新增本次文件并精确 stage。
- 如果 push 失败：保留本地提交，并在 memory 中记录失败原因和下一步。
