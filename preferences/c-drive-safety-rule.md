# C 盘安全规则

## 核心约束

涉及 Windows 系统盘时，默认采取保守策略。未经明确确认，不擅自：

- 删除系统盘上的文件或目录。
- 覆盖已有文件。
- 向 Windows、Program Files、ProgramData 等系统/程序目录写入。
- 修改系统级配置、服务、注册表或启动项。
- 清理看似“临时”但用途不明确的用户配置目录。

如果任务确实需要这些操作，先明确：目标路径、为什么需要、会改什么、能否回滚，再取得确认。

## 允许的工作区例外

对用户已经明确作为工作区或临时区使用的路径，可以按当前任务正常读写，例如：

- `%USERPROFILE%\Documents\Codex\` 及明确的项目子目录。
- `%LOCALAPPDATA%\Temp\` 中由本次任务创建且可明确识别的临时文件。
- 用户在当前任务里明确指定的其他系统盘工作目录。

“允许工作区”不等于允许随意清空整个目录。删除或覆盖前仍要确认目标确实属于本任务创建/管理的内容，避免误伤用户已有文件。

## 路径规则

- 公开知识库不记录具体 Windows 用户名。
- 使用 `%USERPROFILE%`、`%LOCALAPPDATA%`、`<WORKSPACE>` 等可移植表达。
- 环境变量也必须先解析并检查真实目标，不能因为用了变量就跳过安全检查。
- 对递归删除、通配符删除和批量移动尤其谨慎。

## 来源

该规则来自用户对系统盘安全的明确长期要求，并在后续 Windows 自动化/安装工作中持续适用。
