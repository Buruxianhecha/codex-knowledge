## 核心交付偏好

- 未验证 = 未完成；命令、产物、集成、宿主、用户路径分层报告。
- 用户实际体验与理论判断冲突时，继续复现和排查。
- “只/仅/不要/不显示/单文件/保持原样”属于排他性约束。
- “修改/整改现有项目”默认是增量变更；未点名的布局、比例、数据和行为默认保护。
- 高难度、多步骤、材料多且可拆分时主动使用多智能体/并行工作流；共享 Schema 后由统一审计角色收口。
- 涉及付费服务时优先低成本测试版验证体验，但本地/Mock/preview 不冒充 production。

## 写作与研究

- 深度、详细、事实边界清楚；一手/官方/原始材料优先。
- 区分事实、分析、建议和无法确认。
- `contributor` 不写成 `lead`；公司自述不写成法律认定；单案例不外推总体因果。
- 时间敏感稿件写资料截止日；数值区分实时、盘中、收盘、预测、实际和修订。
- SHA-256 用于材料版本追踪，不等于事实真实性证明。
- Word/PDF 检查文件名、正文、页眉页脚、作者属性和隐藏元数据。
- 大型提示词按工程规格写目标、现状、必须项、禁止项、状态模型、不变量、输出契约和验收。

## 工程与测试

- 实用主义、轻量优先、先原型后硬化；第二个同接口实现出现时抽公共层。
- 浏览器持久状态按版本化数据库处理：schema、owner、revision、迁移、恢复和完成态。
- Mock/Real 认证差异封装在 Provider。
- API Key、OAuth token、登录态、cookie、AppSecret 默认脱敏，不进仓库和报告。
- “真实阅读时长”等行为指标按有效状态计量，不用页面打开墙钟时间替代。
- 测试报告注明 smoke、单元、行为、构建、压力、CI、浏览器或用户验收的类型/范围。
- 修改现有作品增加负向 diff：既验证该改的，也验证不该改的没有变化。
