# 运行时验证要先于工作流声明

在自动化和桌面脚本里，文档、记忆和配置文件只能说明“应该怎样”，不能证明“现在能不能跑”。

## 适用场景

- `rtk`、`CODEX_HOME`、插件命令、GUI 自动化入口等可能漂移的运行时能力。
- 任何依赖本机环境、Shell、登录态或外部程序安装状态的任务。

## 经验结论

- 先验证当前 shell 的真实可用性，再引用文档约束。
- 如果运行时和文档冲突，以运行时结果为准。
- 记录失败信号和回退路径，比记录“理论流程”更有复用价值。

## 价值

- 减少误报成功。
- 降低在错误前提上反复重试的成本。
- 让后续自动化更容易恢复和排障。
